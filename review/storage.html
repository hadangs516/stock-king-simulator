게임으로서버 업데이트

반복되는 저장 오류 확인

“저장 결과를 확인하지 못했습니다”는 서버 저장 중 오류가 발생했다는 뜻입니다. 이 문구만으로 정확한 원인을 알 수는 없습니다.

2026년 10월 13일 수정본은 저장 시작 전 실패와 저장 결과가 불확실한 경우를 구분합니다. 게임 화면의 자동 배포와 별도로, 기존 Apps Script 서버에 적용해야 합니다.

1. 짧은 진단부터 실행하기

서버를 만든 Google 계정이 필요합니다. 아래 진단은 시트 설정과 API 연결만 읽습니다. 계정·자산·시트·스크립트 속성을 변경하지 않으며 아이디, 비밀번호, 시트 주소를 출력하지 않습니다.

  1. 기존 Apps Script 프로젝트 열기. PC가 편합니다. 휴대폰에서는 브라우저의 데스크톱 사이트 요청 기능을 사용할 수 있습니다.
  2. 상단 함수 목록에 diagnoseStockKingStorage가 이미 있으면 다음 단계로 넘어갑니다. 없으면 왼쪽 파일 옆 ＋ → 스크립트로 저장진단 파일을 추가하고, 아래 짧은 코드로 기본 내용을 교체한 뒤 저장합니다. 기존 Code.gs는 건드리지 않습니다.
    진단 코드 다운로드

  3. 함수 목록에서 diagnoseStockKingStorage → 실행을 누릅니다. 필요한 권한은 서버 소유자 계정으로 확인합니다. 실행 로그에 나온 {"readOnly":true,...} 한 줄을 보내 주세요. 다른 로그나 스크립트 속성 값은 보내지 않아도 됩니다.

진단만 실행할 때는 웹앱 재배포가 필요 없습니다. setupStockKing는 실행하지 마세요. 서비스가 정상이어도 이 진단은 읽기 전용이므로 실제 쓰기 성공을 보장하지 않습니다.

2. 결과에 따라 확인하기

  • SHEETS_SERVICE_MISSING: 편집기 왼쪽 서비스 → ＋ → Google Sheets API → 버전 v4 → 식별자 Sheets → 추가. 이미 있으면 중복 추가하지 않습니다.
  • PERMISSION_OR_API_DISABLED: Sheets API 활성화와 기존 시트의 소유자 접근 권한을 확인합니다. 직접 연결한 표준 Google Cloud 프로젝트를 사용하는 경우 해당 프로젝트에서도 Google Sheets API를 활성화해야 합니다. Google 공식 서비스 설정 안내
  • MEMBERS_SHEET_MISSING 또는 LEDGER_SHEET_MISSING: 기존 데이터 파일의 회원정보·서버원장 시트가 보존되어 있는지 확인해야 합니다. 새 시트를 만들거나 원장을 초기화하지 말고 결과를 보내 주세요.
  • COLUMN_GRID_TOO_SMALL: 기존 시트의 열 수가 저장 범위보다 작습니다. 아래 수정본은 같은 저장 요청 안에서 부족한 열을 확장합니다.
  • QUOTA, TRANSIENT, GRID_LIMIT, UNKNOWN: 오류 종류를 확인한 뒤 원인에 맞춰 처리해야 합니다. lastFailure가 비어 있으면 이전 서버가 원인 종류를 기록하지 않은 상태일 수 있습니다. 아래 수정본 적용 후 오류가 다시 난다면 같은 진단을 실행해 주세요.

3. 준비된 서버 수정본 적용

기존 통합 Code.gs 한 파일을 쓰는 서버 기준입니다. 현재 코드 전체를 먼저 별도로 백업한 다음 기존 서버 업데이트 안내를 따라 수정본을 붙여넣고, 배포 관리 → 현재 배포 수정 → 새 버전으로 갱신합니다. 주소와 기존 실행 계정·접근 권한은 유지합니다.

1단계에서 별도로 만든 저장진단.gs가 있다면, 수정본에도 동일 함수가 포함되므로 전체 코드 교체 후 그 진단 파일만 제거합니다. 여러 서버 파일을 나눠 쓰고 있다면 대응 파일을 갱신하며 중복 함수를 만들지 않습니다.

수정본은 저장 API 호출 전의 설정 오류를 확정 실패로 분류합니다. 실제 저장 뒤 응답을 잃은 경우에는 같은 요청 번호로 확인하여 거래·보상이 두 번 처리되지 않도록 기존 방식을 유지합니다.
