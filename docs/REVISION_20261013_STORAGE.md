# 2026-10-13 반복 저장 오류 점검

## 운영 증상과 아직 확인하지 못한 부분

사용자가 “저장 결과를 확인하지 못했습니다. 같은 요청으로 재시도해 주세요.”가 대부분의 서버 작업에서 반복된다고 보고했다. 공개 무인증 GET 상태 조회는 정상이나, 이는 저장 성공을 뜻하지 않는다. 서버 소유자 인증·실행 기록에 접근할 수 없어 운영 예외의 실제 원인은 미확정이다. Sheets 서비스 누락·권한/API 비활성·할당량·열 범위·일시 오류 중 특정 원인을 단정하지 않는다.

## 확인된 소스 문제와 수정

- 기존 `doPost`는 저장 API 호출 전 준비 단계부터 `committing=true`로 설정했다. 준비 실패도 COMMIT_UNKNOWN으로 반환하여 저장되지 않은 요청까지 같은 요청으로 재시도하게 했다. 이제 실제 atomic batch 호출 직전에만 COMMIT 상태로 전환한다.
- Sheets 서비스/회원정보 시트 누락은 저장 전 REQUEST_FAILED와 제한된 원인 코드로 반환한다. 원장과 계정 기록은 변경되지 않는다. 실제 호출 뒤 응답 유실은 COMMIT_UNKNOWN 및 동일 요청 ID 확인을 유지한다.
- 원장 4열·회원정보 11열보다 작은 기존 시트는 같은 atomic batch 안에서 부족한 열을 추가한다. 행 확장과 원장/계정 미러의 단일 원자적 저장을 유지한다.
- 예외 로그/속성은 원인 종류와 PREPARE/COMMIT 단계만 기록한다. 요청 본문·계정·PIN·시트 ID·키·provider 원문을 추가로 출력하지 않는다.
- `server/StorageDiagnostics.gs`는 구형 서버에도 단독 추가 가능한 읽기 전용 진단이다. 시트 존재/열 수/원장 chunk 개수와 Sheets 메타데이터 API 접근만 읽는다. 계정 행이나 비공개 원장을 읽지 않으며 모든 데이터/속성 변경을 하지 않는다. 저장된 원인 코드는 허용 목록으로 제한한다. API 읽기 정상은 쓰기 성공을 보장하지 않는다.

## 전달 및 적용 경계

- `review/storage.html`에서 짧은 진단 복사·실행·결과별 설정 확인 안내. `deploy/storage-diagnostic.txt`는 진단 소스와 동일하다.
- `review/setup.html`은 2026-10-13 저장 수정본의 전체 복사, Sheets v4/식별자 Sheets 확인, 기존 배포 새 버전 갱신을 안내한다. 별도 임시 저장진단 파일은 통합 코드와 중복되므로 그 파일만 제거하도록 안내했다.
- `deploy/server-update.txt`는 현재 웹 버전 0.1.16의 서버 20개 소스를 결합한 2026-10-13 저장 오류 수정본이다. 상위 `배포자료/20261013_저장오류점검/`에 원본 패키지와 검증 증거를 보존한다. 이전 0.1.12 패키지를 덮어쓰지 않는다.
- 실제 운영 GAS 코드/서비스/데이터 변경·운영 로그인·setupStockKing 실행 없음. 소유자 진단 및 기존 GAS 배포 갱신이 남는다. GitHub 파일 배포를 GAS 적용으로 표시하지 않는다.
- 사용자 추가 요청: 참고 이미지가 없는 화면도 품질이 낮으면 같은 기준으로 수정. 저장 오류 작업 후 이어서 점검한다.

## 검증

- 준비 실패 분류/열 크기 오류/읽기 전용 진단 회귀 테스트는 수정 전 실패를 확인하고 수정 후 통과했다. 실제 저장 후 응답 유실 시 재요청으로 두 번 차감되지 않는 기존 테스트도 유지한다.
- 전체 141개 테스트·20개 서버 파일 문법/정적 참조 검사 확인. 격리 브라우저 안내 페이지 복사/복사 실패 대체/320·375px 가로 넘침 검사 결과는 상위 증거 폴더에 저장한다.
- 별도 코드 리뷰와 공개 전달 결과는 후속 기록에 추가한다. 사용자 기존 기획기록 삭제 및 `docs/V0_UI_GUIDE.md`는 제외한다.
