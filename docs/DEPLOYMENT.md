# 설치와 배포

## 2026-10-13 기존 운영 서버 업데이트

최신 공개 합본은 저장소 밖 `배포자료/20261013_관리자로그인/주식왕_서버_0.1.20.gs`이다. 기존 Code.gs를 보관한 후 이 합본으로 교체하고, **기존 배포 관리 → 편집 → 새 버전 → 배포**로 갱신한다. 최초 관리자 설정에는 별도로 전달한 비공개 통합본을 사용한다. 기존 시트와 웹앱 URL을 유지하며 `setupStockKing`는 재실행하지 않는다. 아래 초기 설치 절은 새 설치에만 해당한다. 소스 커밋·합본 생성은 GAS 배포 완료가 아니다.

GitHub Pages와 Apps Script는 서로 별도 배포입니다. 소스 업로드만으로 서버가 설치되지는 않습니다.

## 1. Apps Script 서버 설치

1. 기존 웹앱의 Apps Script 편집기를 열고 기존 코드/배포를 먼저 보관합니다. 새 프로젝트를 만들어도 됩니다. 기존 스프레드시트 데이터는 이 코드에 임의 연결하지 않습니다.
2. 상위 `배포자료` 폴더의 **`주식왕_서버_0.1.1.gs` 전체**를 Apps Script의 `Code.gs`에 붙여넣습니다. 이 합본에는 서버 코드 전체가 들어 있습니다. 또는 저장소 `server` 폴더의 **모든 `.gs` 파일**을 각각 같은 이름으로 추가할 수 있습니다. **합본 설치와 개별 파일 설치 중 하나만 사용**하며, 파일들을 HTML 파일로 만들지 않습니다. 기존 게임 스크립트는 백업 후 교체하여 동일한 `doGet`/`doPost`가 중복되지 않게 합니다.
3. 프로젝트 설정 → `appsscript.json 매니페스트 파일 표시`를 켜고 `server/appsscript.json` 내용을 붙여넣습니다. 서비스에 Google Sheets API v4가 표시되는지 확인합니다. 표준 Cloud 프로젝트를 연결했다면 그 프로젝트에서도 Sheets API를 활성화합니다.
4. 함수 목록에서 `setupStockKing`을 **한 번** 실행하고 Google 권한을 승인합니다. 전용 스프레드시트와 5분 트리거를 생성합니다. 실행 로그의 데이터 시트 링크를 확인합니다. 기존 사용자 시트를 덮어쓰지 않습니다. 재실행하면 덮어쓰기 대신 오류로 중단합니다.
5. 트리거 화면에 `marketTick` 5분 간격이 하나 있는지 확인합니다. 누락되었다면 `installMarketTrigger`를 실행합니다. `marketTick` 수동 실행 후 스크립트 속성 `LAST_TICK_MS`, `LAST_TICK_AT`가 갱신되는지 확인합니다.
6. 배포 → 새 배포 → 웹 앱. **실행 사용자: 나**, **액세스: 모든 사용자**. 승인 후 `/exec` URL을 복사합니다. Workspace 정책상 익명 웹앱이 금지되어 있다면 해당 제한을 해결할 때까지 연결되지 않습니다.
7. `/exec` 주소를 열어 `service: stock-king`, `version: 1` 응답을 확인합니다. `SETUP_REQUIRED`이면 설치/시트 접근을 확인합니다.
8. `js/config.js`의 `API_URL`을 배포 URL로 설정하고 main에 커밋·푸시합니다. 현재 파일에는 기획기록의 제공 URL을 넣되 서비스 응답을 검증하며, 기존 서버 기능을 가정하지 않습니다.
9. 이후 서버 코드 변경은 저장만으로 서비스에 반영되지 않습니다. 배포 → 배포 관리 → 편집 → **새 버전** → 배포합니다. 같은 배포를 갱신하면 `/exec` 주소를 유지할 수 있습니다.

## 2. 관리자 일반 로그인 — 최초 설정은 비공개 통합본

서버 소유자에게 전달한 비공개 통합본을 기존 Code.gs에 적용하고 기존 웹앱 배포를 새 버전으로 갱신합니다. 실제 관리자 암호와 검증값은 공개 저장소에 넣지 않습니다. 공개 `deploy/server-update.txt`에는 암호 검증값이 포함되지 않으므로 최초 설정에 사용할 수 없습니다.

설정 후 일반 로그인 화면에서 관리자 아이디와 지정한 비밀번호를 입력하면 바로 관리자 화면이 열립니다. 별도 회원가입, 로그인 화면의 관리자 입력란, 추가 암호 안내는 없습니다. 서버는 관리자 역할과 현재 로그인 세션을 확인하며, 15분 인증을 자동 갱신합니다. 기존 접속이 있으면 접속 전환을 확인합니다. 최초 설정 이후 공개 통합본으로 업데이트해도 비공개 스크립트 속성은 유지됩니다. 기존 시트, 서명키와 트리거를 초기화하지 않습니다.

기존 `ADMIN_NAMES`와 별도 강화 암호로 등록한 다른 운영 계정은 유지됩니다. 해당 계정은 설정 → 관리자 모드에서 기존 강화 암호로 인증합니다.

### 설치 자료를 다시 만들 때

저장소에서 `node tools/package-server.cjs`를 실행하면 저장소 밖 상위 `배포자료` 폴더에 합본 `.gs`, `appsscript.json`, 설치 순서를 만듭니다. 실제 암호나 계정 데이터는 포함하지 않습니다. 프런트엔드 실행에는 이 명령이나 Node.js가 필요하지 않습니다.

## 3. GitHub Pages

- 저장소 Settings → Pages → Deploy from a branch → `main`, `/ (root)`.
- 주소: https://hadangs516.github.io/stock-king-simulator/
- `index.html`, CSS, JS, 아이콘, manifest, service worker를 루트 구조 그대로 유지합니다. npm 설치/빌드가 필요하지 않습니다.
- 서비스 워커는 앱 파일만 저장합니다. API 응답·PIN·계정 데이터는 캐시하지 않고, 오프라인에서는 거래를 확정하지 않습니다.

## 4. 실제 연결 확인 순서

- 데스크톱에서 가입(앞자리 0 PIN) → 로그아웃/로그인 → 매수 영수증 → 새로고침 후 보유 확인.
- 두 브라우저로 같은 계정 로그인 → 중복 안내 취소 시 기존 접속 유지 → 로그인 확정 시 기존 접속 종료·새 접속 성공 → 이전 접속의 조회/거래 거절 확인. 같은 세션의 여러 탭에서는 예약 잠금/취소와 중복 체결·이중 매도 방지도 확인.
- 관리자 강화 인증 → 선택 공지/보상 → 일반 계정의 대상 범위·수령 확인.
- 관리자 대리 화면 → 대상 표시 → 매매 → 돌아가기 → 대상 로그인/플레이 통계 증가 없음 확인.
- 모바일 320px 폭·키보드·PWA 설치·BGM/효과음 독립 조절, 기기 움직임 줄이기 확인.
- Apps Script 실행 목록에서 5분 트리거 시간/오류/일일 사용량을 측정합니다. 동시 접속 인원을 측정 없이 보장하지 않습니다.

## 아직 필요한 외부 연결

외부 웹 푸시 발송 서비스와 키는 제공되지 않았습니다. 앱 내 알림은 사용할 수 있으나 닫힌 앱으로의 웹 푸시 발송은 아직 연결되지 않았습니다. 설치만으로 푸시가 활성화되었다고 표시하지 않습니다.

## 운영 데이터

기존 형식은 `서버원장`에 30,000자 JSON 조각을 보관합니다. v0.1.21은 같은 비공개 문서의 `서버구획`에 현재 상태와 종목별 전체 시세를 압축해 나누어 저장할 수 있습니다. 기본값은 기존 형식이며 코드 저장만으로 장부가 전환되지 않습니다. 변경한 구획과 회원 행은 원자적 Sheets 배치로 함께 저장합니다. 캐시는 현재 메타데이터 해시가 일치하는 사본만 쓰고, 사본이 없거나 손상되면 시트를 읽습니다.

일반 계정 PIN은 기존대로 비공개 시트에 보존하며, 관리자 검증 설정·서명키·계정과 세션을 유지합니다. 시트는 일반 플레이어와 공유하지 않습니다. 거래·예약·권리·감사 기록과 보관 중인 원본 시세를 삭제하지 않습니다. 그래프 시세는 기존 7일 분봉·90일 시간봉·이후 일봉 정책을 그대로 따릅니다.

### 기존 서버의 장부 전환

1. 현재 Code.gs의 비공개 관리자 설정을 보존한 통합본을 저장합니다. 초기 설치 `setupStockKing`를 실행하지 않습니다.
2. 기존 웹앱 배포를 **새 버전**으로 갱신합니다. 기존 URL과 실행 계정·접근 범위를 유지합니다. 새 코드는 두 장부 형식을 모두 읽습니다.
3. 실행할 함수에서 `enableSegmentedStockKingStorage`를 선택하고 실행합니다. 서버 잠금에서 구획별 압축 복원 사전 대조 후 한 번의 원자적 배치로 전환하며, 실제 전체 상태와 모든 시세의 키 순서를 정규화한 해시를 다시 대조합니다. 성공 로그는 개인정보 없는 `changed:true, format:2, retainedHistory:true`입니다. 이미 전환했으면 변경하지 않습니다.
4. `diagnoseStockKingStorage`를 실행해 형식 2, 구획 시트·기본 구획·시세 구획 및 Sheets API 정상 여부를 확인합니다. 원장 셀이나 회원 행을 직접 수정하지 않습니다.
5. 운영 응답 시간과 실행량을 확인합니다. Google 서비스 응답 지연은 남을 수 있으므로 특정 동시접속 인원을 보장하지 않습니다.

### 현재 데이터를 유지한 역전환

v0.1.21의 `restoreLegacyStockKingStorage`를 실행하면 현재 계정·거래·전체 시세를 기존 형식으로 다시 원자적으로 저장합니다. 과거 백업으로 덮어쓰는 방식이 아닙니다. 형식 2 상태에서 옛 서버 버전만 배포하면 옛 코드가 읽지 못하므로, 먼저 역전환 후 옛 버전을 적용합니다. 전환 응답이 유실됐으면 진단으로 현재 형식을 확인하고 동일 전환 함수를 다시 실행할 수 있습니다.
