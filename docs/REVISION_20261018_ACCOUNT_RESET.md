# 2026-10-18 계정 초기화 저장 오류

계정 초기화만 실패하고 삭제·로그아웃은 정상인 문제를 수정했다. 초기화가 만드는 새 계정에 `lastLogin`이 없어, 회원정보 행을 저장할 때 `King.stamp(undefined)`의 날짜 변환이 실패했다. 서버는 이를 저장 준비 단계의 `REQUEST_FAILED / UNKNOWN`으로 분류해 “운영자가 서버 저장 설정을 확인해야 합니다”라고 안내했다. 삭제는 해당 계정 행을 제거하므로 이 경로를 피했다.

`server/AccountLifecycle.gs`에서 초기화 계정의 `lastLogin`을 초기화 시각으로 설정한다. 로그인 횟수는 기존대로 0이며 다음 로그인 시 1이 된다. 인증·PIN·프로필·설정·초기화 범위와 저장 형식은 변경하지 않았다. 제품 버전은 0.1.24를 유지하며 서버 수정만 배포한다.

## 검증

- 새 회귀 테스트는 실제 `doPost` → 저장 → 캐시 제거 → 재로딩 → 재로그인 경로를 저장 형식1·2에서 각각 실행한다.
- 수정 전 두 테스트 모두 같은 오류 안내로 실패했고, 수정 후 통과했다. 독립 검토에서도 수정 제거 시 두 형식 모두 저장 배치 없이 실패함을 확인했다.
- 초기화 후 새 회차, 진행 기록 삭제, 인증·프로필·설정 보존, 이전 세션 무효화, 최초 보상 재요청 중복 방지, 다른 계정·공유 시장 보존, 삭제·로그아웃을 검증했다.
- `npm test`: 217개 통과, 실패 0. 관련 인증·생애주기 테스트 15개 통과.
- `npm run check`: 서버22파일, manifest, HTML, JS 문법·참조 검사 통과. 제한 환경의 하위 프로세스 차단 후 동일 검사를 승인된 실행 환경에서 완료했다.
- 독립 코드 검토: 차단할 문제 없음.
